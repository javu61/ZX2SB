MANUAL DE USUARIO – ZX2SB
Transpilador de ZX BASIC a SuperBASIC (QL)


¿QUÉ ES ZX2SB?

ZX2SB es una herramienta de línea de comandos que convierte programas escritos en ZX BASIC en un fichero de texto a SuperBASIC del Sinclair QL.

El objetivo es:
 - Mantener la semántica original del ZX BASIC
 - Conservar la estructura del programa
 - Generar un código SuperBASIC legible, estructurado, renumerado e indentado

ORIGEN
El origen debe ser un fichero de texto con un programa ZXBasic válido. No se permiten sentencias nuevas, ni sintáxis diferentes a la que admite un
Spectrum. Solo hay ligeros cambios permitidos sobre esta norma:

 - Las variables en ZXBasic admiten letras, números y el espacio en blanco en su nombre, siempre comenzando por una letra. Los espacios en blanco se ignoran, por tanto A B es la misma variable que AB. Esto produce inconsistencias del tipo LET P I = 5 : PRINT P I, PI imprime 5 y 3.14, ya que PI sin espacio es una sentencia válida en ZXBasic. En ZX2SB se cambian los espacios por un subrayado _ para compatibilizar con el QB, y se emite un warning ya que entonces A B se transpila como A_B, y ya no será igual que AB, lo que quizá provoque un error en la ejecución. 
 - El proceso se saltará las líneas vacías sin dar error, ya que no afectan realmente al programa fuente, solo aportan legibilidad.
 - El proceso añade siempre al final una línea de STOP. Esto sirve para separar el programa de posibles adicciones posteriores al final del mismo,
   de forma que sea sencillo incluirlas pues no alteran el comportamiento del programa original (ver renumerador).
 
ESTRUCTURA

Utiliza la estructura de un compilador clásico, por lo que el proceso se realiza en varias fases:
 - Lexer: Analizador léxico (Lexer)
 - Parser: Analizador sintáctico (Parser)
 - Semantic: Analizador semántico (Semantic)
 - Generador: Generador de Código SuperBASIC
 - Renumerador: Renumerador del código final

ZX2SB es el director del proyecto, irá llamando a todos los módulos uno a uno
en el orden adecuado para generar el fichero final.


USO BÁSICO
 Se llama al programa usando el comando:
	ZX2SB Fichero_de_Entrada [Fichero_de_Salida] [opciones] 
	
Este comando ejecuta automáticamente todas las fases del proceso y genera el fichero SuperBASIC final.
Si se llama sin parámetros, o con parámetros erróneos, se presentará en la pantalla un resumen
de su propósito y de las opciones que soporta.

Los parámetros que se pueden usar son:
 - Fichero_de_Entrada: El que se va a procesar con el módulo. Automáticamente se cambiará o añadirá la extensión apropiada al nombre según el módulo.
 - Fichero_de_Salida.: Opcional. Solo se usará en el director o el renumerador, es el nombre del fichero final que se desea generar.
                       Si no se indica será el mismo que el de entrada cambiando o añadiendo la extensión .SB.
                       En el resto de módulos se usará el mimso nombre del fichero de entrada, al que se añade o modicia la extensión.
 - Opciones..........: Las posibles a usar son
               -s   Modo Silencioso. No muestra las líneas mientras se procesan.
               -v   Modo Verbose. Muestra más información. Anula -s
               -nw  Modo No Warnings. No se muestran los warnings ni paran el proceso.
               -ce  Modo Continuar si Errores. No se para al encontrar un error, el resultado final se indica y los errores se ven en el LOG.
               -b   Modo Batch. No muestra nada en pantalla ni interactúa. Activa -s -ce y Anula -v -nw
         
               -nc  Modo Sin Comentarios. No añade los comentarios del fichero de origen en el destino.
               -d   Modo Debug. Añade la línea del fichero original como un comentario sin número de línea.
         
               -fn  Las sentencias no soportadas generan:
                      -f0: un error en la ejecución (si no se indica nada se usa esta opción).
                      -f1: un mensaje en la ejecución.
                      -f2: son ignoradas.
					  
               -rbn La renumeración comienza en n (si se omite se asume -rb1000)
               -rpn La renumeración irá de n en n (si se omite se asume -rp10)
               -in  Se indenta de n en n columnas (si se omite se asume -in2)		
			   
FICHERO DE LOG
Todos los módulos generan un fichero de log, con el mismo nombre del fichero de entrada y extensión .LOG, dentro está la salida del
proceso, con sus errores si los hay.

MÓDULOS DEL SISTEMA

3.1 ZX2SB.exe 
El Director es el módulo principal. Sus funciones son:
 - Coordina todos los módulos
 - Ejecuta el pipeline completo
 - Gestiona ficheros intermedios
 - Pregunta una sola vez si hay que sobrescribir ficheros existentes
 - Controla errores y avisos

Entrada.: Fichero con el programa en ZXBasic
Salida..: Fichero con el programa SuperBasic ejecutable en un Sinclair QL estándar. La extensión será siempre .SB

3.2 JLexer (Analizador léxico)
Lee el fichero ZX BASIC original y lo convierte en tokens. Comprueba:
 - Que cada línea tiene número de línea
 - Que existe separación entre número de línea y sentencia (por ejemplo: “10 REM”, no “10REM”)
 - Que no hay caracteres inválidos

 Errores típicos:
 - Línea sin número
 - Falta de espacio tras el número de línea
 - Caracteres no permitidos

Entrada.: Fichero con el programa en ZXBasic
Salida..: Fichero con los tokens, se ubicará el mismo directorio y usando el mismo nombre del fichero de origen, pero con extensión .TOK
			   
3.3 Parser (Analizador sintáctico)
Convierte los tokens en un IR estructurado.
Funciones:
 - Valida la sintaxis del ZX BASIC
 - Separa sentencias con “:”
 - Trata “IF … THEN” como separador de sentencias
 - Permite cualquier sentencia válida tras THEN (PRINT, READ, etc.)

Errores típicos:
 - Falta de THEN
 - Uso incorrecto de “:”
 - Sentencias no reconocidas

Entrada.: Fichero con los tokens generados a partir del programa en ZXBasic con extensión .TOK
Salida..: Fichero con el AST del programa en modo de texto IR, con extensión .IRP

3.4 Analizador Semántico
Analiza el significado del programa.
Funciones:
 - Control de variables
 - Control de FOR / NEXT
 - Control de GOSUB / RETURN
 - Gestión de READ / DATA / RESTORE
 - Emisión de avisos (warnings)

Entrada.: Fichero con el IRP generado a partir del parser, con extensión .IRP
Salida..: Fichero con el AST validado y ajustado del programa en modo de texto IR, con extensión .IRS
          Fichero con la tabla de Variables usadas en el programa con extensión .Var
          Fichero con al tabla de instrucciones DATA usadas en el programa, con extensión .DAT
		    Estos dos ficheros no se usan fuera de los procesos actuales del semántico, pero se conservan como referencia

3.5 Generador
Convierte el IR en SuperBASIC del QL.
Características:
 - Todo IF se convierte en un bloque con END IF
 - Los IF múltiples se anidan correctamente
 - No se elimina código inalcanzable
 - No se optimiza la lógica

Entrada.: Fichero con el IRS generado a partir del semántico, con extensión .IRS
Salida..: Fichero con el programa SuperBasic Generado, con extensión .SBG, usando numeración de líneas no final.

3.6 Renumerador (fase final)
Es la última fase del proceso. Renumera el programa completamente, ajustando los saltos que existan.
El proceso añade una línea final con un STOP, y todos los saltos a líneas fuera del programa los apunta
a esta línea. 

Funciones:
 - Renumera el programa completo
 - Ajusta todos los saltos (GOTO, GOSUB, RESTORE)
 - Añade una línea de STOP final.
 - Aplica indentación automática
 - Detecta construcciones dudosas y emite warnings

Ejemplos de warnings:
 - FOR sin NEXT (no define un bucle real)
 - Saltos a líneas inexistentes en el original

Entrada.: Fichero con el programa generado a partir del semántico, con extensión .SBG
Salida..: Fichero SuperBASIC final, listo para usar, renumerado, con extensión .SB



TRATAMIENTO DEL IF
 - Todo IF se genera como bloque, incluso si solo tiene una sentencia. Por ejemplo
	ZX BASIC:               IF A=1 THEN PRINT A
				
	SuperBASIC generado:	IF A = 1 THEN
								PRINT A
							END IF
							
 - Si hay varios IF múltiples encadenados en la misma línea se anidan correctamente.
 - Los IF de una sola línea con acción directa (por ejemplo IF I=5 THEN GOTO 3750) no generan indentación adicional.
 - En proximas versiones se optimizarám los IF de una sola sentencia creando una sola línea para ellos

TRATAMIENTO DEL FOR / NEXT
- FOR multilinea:
  - Abre bloque
  - Requiere NEXT, pero se genera END FOR

- No se tratan errores del tipo FOR de una sola línea: FOR I=1 TO 10 : PRINT I
  - Es válido en ZX BASIC
  - Pero no define un bucle por no disponer de un NEXT
  - Por tanto No genera END FOR y se emite un warning



INDENTACIÓN
El renumerador aplica indentación automática con estas reglas:
 - IF … THEN abre bloque (si es multilinea)
 - END IF cierra bloque
 - FOR abre bloque solo si no es de una sola línea
 - END FOR cierra bloque

La indentación es solo visual y no afecta a la lógica.

SENTENCIAS ESPECIALES
 - READ / DATA / RESTORE: ZX2SB las soporta completamente
 
 - PRINT: El PRINT básico funciona igual en ambos sistemas, pero las paradas
          de tabulación al usar comas como separador son diferentes en ambos sistemas.
		  Se separan los campos de impresión de los atributos, así 
			ZXBasic: PRINT INK 4;"A" 
			genera:  INK 4
                     PRINT "A"
					 
 - "RND", "PI", "CHR$", "STR$", "LEN", "VAL", "VAL$", "CODE"
   Funcionan de manera similar en ambos sistemas

 - "BIN" No existe en SuperBASIC, pero se incluye una función propia que hace
         lo mismo.

 - "ATTR", "POINT", "SCREEN$": No son soportadas en SuperBASIC
   Quizá se puedan simular en próximas versiones
   
 - "PEEK", "POKE": No son soportadas ni lo pueden ser
